# 앱과 개폐기 NFC HCE 통신 v2

새 카드 추가 UI의 시간·마릿수 설정을 손실 없이 전달하는 오프라인 규약입니다. 온라인 [API MQTT v2](gate-control-v2.md)의 필드와 토픽은 변경하지 않습니다. NFC 적용건은 온라인 `/commands/current` 조회 대상이 아니며 상태는 휴대폰 로컬에 남습니다.

## 전송 방식

- AID `F0 57 42 45 45`와 SELECT APDU는 유지합니다.
- Android는 SELECT 응답으로 ASCII 명령과 `90 00`을 반환합니다.
- 새 명령의 접두사는 `WB2`. 제목·메모·MAC·서버 commandId는 명령에 싣지 않습니다. 태깅한 리더기가 대상이고, 기기 MAC은 결과에서 받습니다.
- 날짜는 기존 별도 APDU `80 54 00 00 00`으로 요청합니다. 응답은 태깅 시점의 `yyyy-MM-dd-HH:mm`입니다.
- 구형 펌웨어는 WB2를 해석하지 못하고 거절합니다. 신규 펌웨어는 기존 WBEE 카드도 해석합니다.
- 앱은 네이티브 모듈의 `getProtocolVersion() >= 2`를 확인합니다. 구형 APK가 새 필드를 무시하고 다른 카드를 실행하는 것을 방지합니다.

## 짧은 명령 형식

각 숫자는 10진수이며 구분자는 `|`입니다. 시간은 자정부터의 분, 반복은 0/1입니다.

| 카드 | 형식 | 예시 |
| --- | --- | --- |
| ON | WB2\|O | `WB2\|O` |
| OFF | WB2\|F | `WB2\|F` |
| COUNT 조회 | WB2\|S | `WB2\|S` |
| 열기 예약 | WB2\|A\|분\|반복 | `WB2\|A\|540\|0` |
| 닫기 예약 | WB2\|Z\|분\|반복 | `WB2\|Z\|1440\|1` |
| 시간대 운영 | WB2\|W\|시작분\|종료분\|반복 | `WB2\|W\|1380\|1440\|1` |
| 24시간 교대 | WB2\|T\|시작방향\|반복 | `WB2\|T\|0\|1` |
| 기존 농약방제 | WB2\|L\|일수 | `WB2\|L\|3` |
| 벌 마릿수 제어 | WB2\|C\|low\|high\|요일\|시작분\|종료분\|within\|above | `WB2\|C\|3\|12\|42\|0\|1440\|3\|1` |

교대 시작방향은 0=close_first, 1=open_first입니다. L은 기존 로컬 NFC 카드 호환이며 온라인 cardType에 추가하지 않습니다. `WB2|X`는 앱이 잘못된 카드를 거절할 때 이전 카드의 대기를 해제하기 위한 비실행 값입니다. 펌웨어는 X를 오류로 거절하며 기존 규칙을 바꾸지 않습니다.

시간 시작은 0~1439, 종료는 0~1440분입니다. 1440은 24:00이며 23:59로 줄이지 않습니다. TIME 스케줄 내부에서는 종료 1440을 다음 자정으로 해석합니다. 기존 로컬 TIME 카드의 분 단위·야간 구간 호환은 유지하고 새 UI는 30분 단위와 WINDOW 최소 1시간 차이를 적용합니다.

## 마릿수 설정

- low/high: `0 ≤ low ≤ high ≤ 99`. 99는 실제 99이며 무제한 기능은 없습니다.
- 요일: bit 0=일요일, 1=월요일, …, 6=토요일. 42=월수금, 127=매일, 0=단발성.
- 시간: 시작 < 종료, 30분 단위. 0~1440은 종일.
- within/above: bit 0=입구 열림, bit 1=출구 열림.

| 값 | 입구 | 출구 |
| --- | --- | --- |
| 0 | 닫힘 | 닫힘 |
| 1 | 열림 | 닫힘 |
| 2 | 닫힘 | 열림 |
| 3 | 열림 | 열림 |

현재 활동 수는 부팅 후 누적 exit_out − entrance_in입니다. signed 연산으로 음수가 큰 양수로 바뀌는 것을 막습니다.

- low 미만: 입구 닫힘, 출구 열림.
- low 이상 high 미만: within.
- high 이상: above. low=high이면 within 구간은 비어 있습니다.
- 지정 요일 또는 시간 밖: 양쪽 열림.
- 단발성: 현재 또는 다음 유효 시간 구간 한 번만 적용. 구간 시작 전에는 양쪽 열림, 구간이 끝나면 규칙을 해제하고 양쪽 열림. 이미 오늘 구간이 지났으면 다음 날 구간을 선택합니다. 종일 단발성은 다음 자정에 종료합니다.
- 반복: 구간 밖에는 양쪽을 열되 설정은 유지하고 다음 지정 시간에 재개합니다.
- 매 통과 이벤트와 매초 타이머에서 재평가하므로 벌이 지나가지 않아도 시간 경계가 적용됩니다.
- 새 제어 카드는 이전 규칙을 교체합니다. COUNT 조회 카드는 기존 규칙을 변경하지 않습니다. 오프라인에서 규칙을 해제하고 양쪽을 열려면 ON 카드를 태깅합니다. 온라인 targetCommandId 취소를 NFC에 임의로 추가하지 않습니다.

COUNT 규칙은 현재 RAM에 보관하며 재부팅 후 자동 복구하지 않습니다. TIME의 기존 NVS 저장은 유지합니다. 앱의 로컬 상태는 마지막 태깅 결과이며 실시간 기기 조회가 아닙니다.

## 길이와 결과 수신

RC522 FIFO는 64바이트이고 현재 SELECT 응답의 ISO DEP chaining은 지원하지 않습니다. 최대 길이 COUNT 명령은 `WB2|C|99|99|127|1410|1440|3|3`으로 **29 ASCII 바이트**입니다. PCB와 선택 필드, 상태워드, CRC를 포함해도 단일 프레임 안에 들어가도록 앱과 네이티브는 명령을 최대 48바이트로 제한합니다. 길거나 잘못된 입력을 자르거나 다른 모드로 치환하지 않고 거절합니다.

기기 결과 APDU는 `80 52 00 00 Lc <text>`입니다. PCB 1 + APDU 5 + text + CRC 2가 64 이하이므로 결과 텍스트는 최대 56바이트입니다. 새 카드 성공 응답은 다음처럼 짧게 유지합니다.

```text
OK|count_control|applied|D=AA:BB:CC:DD:EE:FF
```

v2 결과에서는 긴 누적 카운터를 제외합니다. 카운터와 통계는 기존 `0x53` 통계 APDU로 따로 받습니다. 펌웨어의 기존 `SF|ID|순번|마지막여부|조각` 형식을 앱에서 조립합니다. 데이터는 조각당 최대 45바이트, 프레임당 텍스트 최대 56바이트이며 완성된 ST 메시지만 화면에 전달합니다. 중복 조각은 무시하고 누락·순서 오류·96바이트 초과는 거절합니다. 기존 비분할 ST 메시지도 받습니다.

응답 OK는 제어 설정 수락과 서보 명령의 성공입니다. 센서 안전 인터록으로 실제 이동이 보류될 수 있으며, SG90 위치 피드백은 없습니다.

### 한 번 태깅할 때의 왕복과 알림

카드 SELECT 응답 → 휴대폰 시간 요청/응답 → 개폐기 규칙 적용 → 결과 보고/폰 ACK → 통계 조각별 보고/폰 ACK 순서입니다. 29바이트는 카드 명령의 최대 길이이며 전체 태깅이 한 번의 전송으로 끝난다는 뜻이 아닙니다. 통계 양에 따라 왕복 횟수가 늘어납니다.

앱의 적용 성공 알림은 결과 보고를 받았을 때 표시됩니다. 이후 통계 전송이 이어지므로 이 알림이 모든 통계 수신 완료나 실제 문 위치 확인을 뜻하지는 않습니다. 카드 팝업은 적용 알림까지 계속 대고 있으라고 안내하며, 성공 후에는 통계를 받으려면 더 대고 있으라고 안내합니다. 카드 선택 직후의 성공 진동은 제거했습니다.

실물 확인이 필요한 기존 통신 제약: 결과 APDU 전송 실패 시 자동 결과 재전송은 없으며, 같은 카드를 2초 이내 다시 태깅하면 중복 억제로 결과 알림도 생략될 수 있습니다. 알림을 못 받았다고 미적용으로 단정할 수 없습니다. 폰을 떼고 2초 이상 기다린 뒤 재태깅해야 합니다. RC522 응답 타임아웃과 폰 기종별 ISO-DEP 동작은 PC 파서 테스트로 검증할 수 없습니다.

## 변경 파일과 검증

앱: `nfcWire.ts`, `webeeHce.ts`, `nfcStatsFragments.ts`, 카드 추가 UI, 로컬 runtime. Android 소스와 이를 다시 생성하는 `plugins/withWeBeeHce.js`를 함께 수정합니다.

펌웨어: `D:/open/main/nfc_payload.c`, `nfc_payload.h`, `app_main.c`. 기존 서보 안전 인터록을 거쳐 움직입니다.

```powershell
node --test src/features/door-opener/model/nfcWire.test.cjs src/features/door-opener/model/nfcStatsFragments.test.cjs
powershell -File scripts/test-gate-nfc-firmware.ps1
```

PC 테스트는 실제 펌웨어 파서·COUNT 제어 코드에 RTC/서보/FreeRTOS mock을 연결합니다. 실제 Android 빌드, ESP-IDF 빌드, NFC 리더기 통신, 플래시를 대신하지 않습니다. 배포 시 앱 네이티브 모듈과 개폐기 펌웨어를 함께 업데이트해야 합니다.
