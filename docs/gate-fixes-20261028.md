# 개폐기 NFC 누적값 / 중복 온라인 명령 수정

- `ST|BEGIN`은 전체 스냅샷 교체 신호가 아니다. 펌웨어는 전송 완료한 닫힌 버킷을 생략하므로 앱은 기기별로 기존 시간대·온습도 기록을 유지하고 같은 구간만 갱신한다.
- `ST|BOOT|D=<MAC>|<in>,<out>,<in>,<out>|S=<8자리 대문자 hex>`에 부팅 세션을 추가했다. 이전 앱은 첫 counts 필드를 계속 읽을 수 있다. 새 앱은 세션별 마지막 카운터와 앱 누적값을 함께 저장한다. 같은 세션은 증가분만, 새 세션은 새 카운터를 합산한다. 구형 펌웨어는 카운터 감소로만 초기화를 추정할 수 있다.
- 앱 시작 직후 받은 통계는 저장된 캐시 복원이 끝난 뒤 적용한다. 초기 복원으로 방금 수신한 값이 덮이지 않게 한다.
- 기기에 마지막으로 적용한 제어 내용이 동일하고 여전히 유효하면 온라인 결과는 `status=OK`, `detail=ALREADY_APPLIED`다. NFC/온라인 공용 제어 잠금 안에서 판단한다. 시간표를 다시 시작하거나 확인용 서보 동작을 반복하지 않는다. 새로운 온라인 commandId에 대한 결과는 정상 발행한다.
- 앱은 서버가 전달한 `SUCCESS / ALREADY_APPLIED`를 열림·닫힘·동일 설정 안내로 표시한다. POST가 이미 완료 결과를 반환하면 재조회하지 않는다. 기기 연결이 끊겼거나 결과를 받지 못한 경우에는 성공으로 간주하지 않는다.

## 검증과 남은 확인

- 앱 회귀 테스트 17개 통과: 7회 수신, 중복 태깅, 캐시 복원, 새 세션 3회 수신 시 10회 유지, 같은 시간대 기록 병합, 즉시 완료 응답 처리.
- 펌웨어 호스트 테스트 통과: NFC 제어/온라인 전환, 같은 ON 명령의 ALREADY_APPLIED 응답과 재동작 생략, MQTT 중복 수신, 서보 PWM.
- ESP-IDF 6.0.1 전체 빌드 통과.
- `stats` 콘솔 명령에서 145개 버킷 스냅샷이 4 KiB 태스크 스택을 넘겨 실제 재부팅되는 것을 재현했다. 스냅샷을 정적 메모리로 이동했다.
- COM11에 최종 펌웨어를 플래시하고 쓰기 해시를 검증했다. 같은 기기에서 `stats`를 3번 연속 조회하고 `health` 응답까지 확인했다. 재부팅/스택 초과 없이 완료됐고 콘솔 스택 여유가 보고됐다.
- 기기의 저장된 Wi-Fi 연결 실패 로그를 확인했다. 앱에서 서버가 명확하게 오프라인으로 판정한 경우 명령 전송 대신 Wi-Fi 연결 안내를 표시한다. 연결 조회 미지원 서버에서는 기존 명령 경로를 유지한다.
- 전체 TypeScript 검사에는 다른 화면의 오류 132개가 있으며 이번 개폐기 변경 파일의 진단은 없다.
- COM11의 기기 ID `48:9D:31:C4:E4:F0`에서 기존 ON 출력이 180도 / 2500us임을 확인했다. 이 출력은 현재 코드의 최대값이다. 사진상 남은 구멍 가림은 실물에서 서보 혼/덮개 장착과 작동 범위를 확인해야 한다. 완전 개방은 검증하지 않았다.
- 앱에 한 번도 수신되지 않은 통과 기록은 전원 손실 시 복구할 수 없다. 기기의 통과 카운터는 RAM이며 이번 변경은 앱이 이미 수신한 누적값을 보존한다. 이전 앱에서 이미 덮어쓴 기록을 자동 복원하지는 못한다.
- 휴대폰 앱 설치 및 실제 NFC→온라인 명령→서버 결과→앱 안내의 전체 흐름은 별도 실기기 확인이 필요하다.
